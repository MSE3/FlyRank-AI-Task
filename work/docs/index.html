FlyRank ML Internship — Capstone — Refresh / Content Opportunity Scoring

Catching Decline Before It's Obvious

A ranked, reason-coded scoring system for finding content worth an editor's attention — built and honestly validated on real FlyRank search-performance data.

Abstract Which of a site's thousands of pages are quietly declining in search performance, and which ones deserve an editor's attention first? Using FlyRank's anonymized search-performance dataset, two candidate signals were audited, a transparent baseline rule was built, and four models — Logistic Regression, Decision Tree, Random Forest, Gradient Boosting — were compared against it on a client-grouped, held-out split. Gradient Boosting delivered the strongest ranking (precision@10% = 0.689, ROC-AUC = 0.632) against a baseline of 0.596 precision@10% (ROC-AUC 0.554). One working assumption — that older content declines more — was tested and found backwards in this data, and a genuine label-construction leak was caught and removed before any modeling began. The result ships as a ranked, reason-coded action queue meant to support an editor's review process, not replace it.
01 — Introduction

The decision this work supports

Large content libraries decay unevenly. Some pages lose clicks quietly for months before anyone notices; others look fine in aggregate traffic charts while their click-through rate quietly falls behind what their search ranking should deliver. An editorial team can only review a fraction of a site's pages in any given sprint — the real decision this project supports is: given limited review capacity, which pages should be looked at first, and why?

This is framed as a content-day, current-state classification problem — not a causal claim about what's driving decline, and not a guarantee that any specific fix will reverse it. It is a triage tool: a ranked queue with a plain-English reason attached to each flagged page, so an editor can decide quickly whether the machine's reasoning holds up.

02 — Data

What this runs on, and what it deliberately excludes

This capstone runs on FlyRank's anonymized internship starter sample — content_refresh_anonymized.csv — 30,000 rows, one row per pseudonymized content item, spanning 32 pseudonymized clients, with trailing-90-day aggregate search performance metrics per item.

Scope, stated plainly: this is the 30k-row starter sample, not the full ~79M-row Hugging Face warehouse release. Every weekly notebook behind this capstone used the same sample; rebuilding fresh against the full warehouse late in the process was judged higher-risk than valuable given the time available. This is a real limitation of this paper's scope, not a hidden one — see Limitations below.

Excluded, and why:

Column(s)Why excluded
trend_pct trend_directionthe label itself — the outcome being predicted
impressions_last_30d impressions_prev_30dproven (not assumed) to reconstruct the label almost exactly — correlation 0.99999 between their implied % change and trend_pct

No client names, domains, URLs, or raw exports appear anywhere in this repository or this page — every identifier here is a pseudonym already anonymized by FlyRank before release.

03 — Methodology

Assumptions, features, and validation design

Label: is_declining = 1 if trend_direction == "down", an observed comparison of recent vs. prior performance — not a subjective editorial rule.

Two signals audited before anything was built:

Staleness (content age) vs. decline rate — verdict: OPPOSITE. Decline rate falls as content ages (31–90 days: 67% declining, n=492 → 365+ days: 43% declining, n=6,360) — the reverse of "older content decays more." A clean, explained negative: raw age is deliberately never used as "older = riskier" anywhere in this model.
CTR vs. search position — verdict: CONFIRMED. CTR rises cleanly with position: deep 0.15% → page_3_5 0.22% → striking 0.32% → page_1 0.65% → top_3 1.48%. This became the backbone of the baseline rule below.

Baseline (the bar every model must beat): flag visible pages (≥500 impressions in 90 days) whose CTR sits under half their position tier's typical rate. No fitted weights — fully explainable, one reason code, one action label.

Features: 90-day performance aggregates (impressions, clicks, sessions, engagement, scroll activity, active days) plus static content attributes (word count, content type, search intent, competition level, CPC) — all knowable without the label's own 30-day comparison window. Missingness in word/char counts is flagged (has_word_count) rather than blind-filled, since missingness tracks content type rather than being random.

Validation design: split grouped by client (70/30), so no client's pages appear in both train and test — confirmed zero overlap. A row-random split would let a model partly memorize client-specific baseline behavior instead of learning transferable content signals.

Honest framing: because the 90-day aggregate features likely still partially overlap the label's own most recent 30 days, this model is a current-state diagnostic — "does this page's present profile resemble other declining pages?" — not a clean past-predicts- future forecast.

04 — Results

Model vs. baseline, same split, same metric

Four methods — Logistic Regression, Decision Tree, Random Forest, Gradient Boosting — evaluated against the baseline rule on the identical held-out, client-grouped test fold. K = top 10% of the test fold (an editor's realistic weekly review capacity); test-fold base rate = 0.559.

Gradient Boosting wins on both metrics and is carried forward. The Decision Tree — included specifically to test whether a simple, readable model was "enough" — barely beat the baseline (0.604 vs. 0.596), showing the added complexity of Gradient Boosting earns its place here rather than being assumed.

Reading the errors: both false-negative and false-positive cases inspected by hand clustered around near-zero-click content (impressions in the single digits, CTR of 0) — genuinely little signal exists to separate "just launched, hasn't earned a click yet" from "declined to near-zero." That is the model's real blind spot, not any one feature or tier.

05 — Limitations & honest framing

What this can't tell you

  • Scope: built on the 30k-row starter sample, not the full warehouse. Directional findings (e.g., "newer content declines more here") may not hold at full scale or evenly across all clients.
  • Window overlap: 90-day aggregate features likely share some calendar time with the label's own most recent 30 days. This is a current-state diagnostic, not a clean forecast — its claims are decision-support, not causal.
  • Client imbalance: history depth varies by client; this starter sample doesn't expose a per-client history-start column, so per-client fairness is unverified here.
  • No causal claim: nothing here proves why a page is declining, or that any recommended fix would reverse it — only that its current profile resembles other declining pages. Language throughout is observed, measured, and directional — never causal.
06 — Ranked recommendations

The action playbook

  1. ctr_below_position_expectation (2,384 flagged pages) — the highest-volume, most actionable reason code: a title/meta-description review for pages ranking well but under-clicking relative to their tier. Start here.
  2. model_flagged_review (612 flagged pages) — no single obvious cause identified by the reason-code rules; route to manual editorial review rather than an automated fix.
  3. young_and_volatile / near_zero_signal / low_active_days (rare in this run) — watch-list only; too little signal yet for a confident action.

Suggested queue order for an editorial sprint: ctr_below_position_expectation first (clear, explainable, highest volume), then model_flagged_review (needs a human look), then treat the remaining reason codes as a monitoring list, not an action list.
